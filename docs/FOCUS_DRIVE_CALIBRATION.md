# Focus Drive 硬件实测、步长公式推导与自适应闭环算法

本文档记录 Sony `CameraEx.startOneShotFocusDrive(dir, speed)` 在 **Sony E PZ 16-50mm F3.5-5.6 OSS**（`maxPosition = 119`）上的真机实测数据、数学拟合过程，以及最终在 [`CameraGoalController.java`](../camera-app/app/src/main/java/com/sony/pmca/webcontrol/CameraGoalController.java) 中落地的自适应闭环控制算法（前端 [`cameraClient.ts`](../web-client/src/api/cameraClient.ts) 统一调用 `highlevel.setFocusPosition` 并严格校验收敛结果）。

---

16 个目标点中 **8 个** 因 `stalled = true` 提前终止（差 `1 ~ 4` 个刻度），且每次移动耗时 `3.5 ~ 10.3 s`；同时旧版前端 `gotoFocus` 未校验 `converged` 与 `position`，导致未到位即直接拍摄。

### 重复性与固定死区排查

连续两次从 `60` 重复走 `56, 52, 48, 44, 40, 36, 32`：

- **Run 1 (`start = 60`)**：`48→50(stalled)`, `36→37(stalled)`, `32→34(stalled)`；而 `40` 到位。
- **Run 2 (`start = 63`)**：`56→62(stalled)`, `52→53(stalled)`, `44→48(stalled)`；而 `48, 40, 36, 32` 全部到位。

结论：停顿**不发生在固定焦距刻度**，不是机械轨道固定死区。

## 3. 数学建模与公式推导

### 3.1 速度倍率识别（固定 `zoom` 对 `speed` 的回归）

观察表 2.4，对每个固定 $z \in \{0, 38, 74, 100\}$，取未受整数向下取整截断的区间（$s \ge 3$）做对数线性回归 $\ln \Delta = a + b \cdot s$：

- $z = 0$：倍率 $r = e^b = 2.6365$，基准 $\hat{\Delta}(0, 5) = 38.64$
- $z = 38$：倍率 $r = e^b = 2.5902$，基准 $\hat{\Delta}(38, 5) = 14.32$
- $z = 74$：倍率 $r = e^b = 2.5136$，基准 $\hat{\Delta}(74, 5) = 8.15$
- $z = 100$：倍率 $r = e^b = 2.6015$，基准 $\hat{\Delta}(100, 5) = 6.98$

不同焦段下的档位公比高度稳定，取全局公比 $r = 2.615$。

### 3.2 焦段缩放曲线拟合（`speed = 5` 基准随 `zoom` 变化）

以 $s = 5$ 为基准，$v_5(z)$ 在 $\{0, 38, 74, 100\}$ 处实测均值分别为 $\{38.6,\, 14.0,\, 7.8,\, 7.0\}$：从 `z = 0` 到 `z = 100` 呈“指数衰减 + 平台下界”特征。拟合模型：

$$v_5(z) = c_0 + c_1 \cdot e^{-k\,z}$$

在 $k \in (0, 0.1)$ 网格搜索并闭式线性回归求 $(c_0, c_1)$，最小平方和误差出现在 $k = 0.0373,\, c_0 = 6.017,\, c_1 = 32.591$（$SSE = 0.1257$）：

- $z = 0$：预测 `38.61` vs 实测 `38.60`
- $z = 38$：预测 `13.91` vs 实测 `14.00`
- $z = 74$：预测 `8.08` vs 实测 `7.80`
- $z = 100$：预测 `6.80` vs 实测 `7.00`

### 3.3 最终预测公式与化简

合并速度公比与焦段缩放曲线，先得到以 $s = 5$ 为基准的原始拟合形式：

$$\Delta(z, s) = \bigl(6.0 + 32.6 \cdot e^{-0.0373\,z}\bigr) \cdot 2.615^{\,s - 5}$$

将常量 $e^{-0.0373} \approx 0.9634$ 与 $2.615^{-5} \approx 0.008178$ 展开并合并到前置系数中，即可化简为更简洁的纯幂次形式（与原式最大偏差 $< 0.08\%$）：

$$\Delta(z, s) = \bigl(0.0491 + 0.2667 \cdot 0.9634^{\,z}\bigr) \cdot 2.615^{\,s}$$

将全部 21 个实测数据点代入公式对比，**平均相对误差为 `4.1%`**：

| Speed | `z = 0` | `z = 38` | `z = 74` | `z = 100` |

| **1** | `0.83` (`1.0`) | `0.30` | `0.17` | `0.15` |
| **2** | `2.16` (`2.33`) | `0.78` | `0.45` | `0.38` |
| **3** | `5.64` (`5.6`) | `2.03` (`2.2`) | `1.18` (`1.4`) | `0.99` (`1.0`) |

## 4. 最终自适应闭环算法

### 4.1 设计要点

1. **焦段感知选档**：读取当前变焦位置 $z$（若无光学变焦信息如定焦头，$z < 0$ 时按保守默认值 `z = 74` 计算），由大到小挑选满足 $\Delta(z, s) \le 0.92 \cdot |\text{target} - \text{current}|$ 的最大 `speed`，避免在广角端大步超调。
2. **避开微步死区**：正常逼近时强制所选速度的预测步长 $\Delta(z, s) \ge 0.75$（例如在长焦端 `z = 74 / 100` 下，`s = 1, 2` 只有 `0.15 ~ 0.45` 刻度，算法自动跳过它们，最低使用 `s = 3`），消除十几次脉冲不动导致的假卡死。
3. **跨目标震荡微调阻尼**：仅当连续在目标两侧反向超调（`reversals >= 2`）且剩余距离 $\le 2$ 时，放开 `0.75` 下限限制，允许下探一档微步精细落点。
4. **固件空打容错与阶梯升速**：由于机身本身会随机忽略部分 `OneShot` 调用：
   - 每次驱动后等待 `200 ms`（覆盖 `95 ~ 166 ms` 的实际响应窗，缩短无效等待）；
   - 位置未变仅累加 `zeroStreak`；每连续 `3` 次无变化临时将当前速度 `+ floor(zeroStreak / 3)`（剩余距离 $\le 3$ 时最多临时提速 `+1`）以突破空打/静摩擦区；
   - 连续 `zeroStreak >= 24` 才真正判定 `stalled = true` 退出（最多允许 `100` 步）。
5. **严禁伪收敛（真假到位校验）**：
   - 相机端（`CameraGoalController.setFocusPosition`）仅当 `|actual - clampedTarget| <= tolerance` 时才返回 `converged = true`；保留手动拧动对焦环抢占检测（`manualOverride`）。
   - 前端 [`cameraClient.ts`](../web-client/src/api/cameraClient.ts) 统一调用 `highlevel.setFocusPosition` 并严格校验返回的 `converged` 与 `position`：若未达到容差范围，直接抛出异常并中止 `runFocusStack`，不再在错误焦距下盲拍。

### 4.2 实机整段验证结果（`60 → 0, step = 4`, 容差 `0`）

算法上线前用完全一致的逻辑在真机分别测试广角（`zoom = 0`）与长焦（`zoom = 77`）：

- **`zoom = 0`**：`16 / 16` 全部精确收敛（误差 `0`），总耗时 **`29.4 s`**（平均 `1.84 s / 步`）。
- **`zoom = 77`**：`16 / 16` 全部精确收敛（误差 `0`），总耗时 **`36.6 s`**（平均 `2.29 s / 步`）。
